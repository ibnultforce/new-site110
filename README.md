# TwinStack Solutions — website

Static site generator for twinstack.net. Markdown in, HTML out. No framework,
no bundler — Node 18+ and one `npm install` (Tailwind only).

```bash
npm install
npm run dev      # preview at http://localhost:4321, rebuilds on save
npm run check    # build + fail on broken links or duplicate URLs
```

## Header

`content/data/navigation.json` → `header`:

- `header.items` — the nav links. Plain `{ label, url }`, or add `children`
  for a dropdown, or `type: "collection"` + `collection: "<name>"` to list a
  collection's entries automatically (no manual updates as pages are added).
- `header.cta` — the single button on the right, `{ label, url }`.

Nothing else contributes to the header. Edit this file only.

## Footer

Same file, two more keys:

- `footer` — array of columns: `{ title, links: [...] }`. A link can be
  `{ label, url }` or `type: "collection"` like the header.
- `legal` — the bottom-row links (privacy, terms, etc.).

## Sitemap, RSS, robots.txt, search index

Fully automatic on every `npm run build` — generated from whatever pages
exist. Nothing to configure. Old-URL redirects go in
`content/data/redirects.json` (`{ from, to, status }`), written to
`dist/_redirects`.

## SEO

Every page's search title, description, focus keyphrase, social image,
canonical URL and noindex are optional frontmatter fields (`metaTitle`,
`metaDescription`, `focusKeyword`, `ogImage`, `ogImageAlt`, `canonical`,
`noindex`); site-wide defaults are in `site.config.json` → `seo`.

```bash
npm run seo                                   # score every page, list what to fix
npm run seo -- about                          # one page, shown as a Google result
npm run seo -- about --title="…" --description="…" --keyword="…"   # set by hand
npm run seo:claude -- about ["direction"]     # Claude writes them from the page
npm run seo:claude -- --all                   # every page that has none yet
npm run seo:report                            # seo-report.html: every page as a search result
```

## Predefined .md files for scaffolding

`npm run scaffold` walks `scripts/site-tree.md`. For any listed path, if
`scripts/site-tree-content/<path>.md` exists (same path, `.html` → `.md`),
that file is written verbatim instead of a generic placeholder — e.g.
`scripts/site-tree-content/contact.md` for the `contact.html` line. Paths
with no matching file scaffold from the generic skeleton as before.

## Static files

- `static/` — copied as-is to the site root in `dist/`, no templating. Use
  for standalone HTML you don't want passed through the build (e.g.
  `static/movies/foo.html` → `/movies/foo.html`).
- `assets/` — CSS/JS/images, copied to `dist/assets/`. `assets/css/main.css`
  is generated by Tailwind from `styles/main.css` — never edit it directly.

## Static information (site-wide facts)

| What | File |
| --- | --- |
| Name, tagline, contact, brand, social | `site.config.json` |
| Nav / footer / header (above) | `content/data/navigation.json` |
| Headline stats, integrations, process | `content/data/company.json` |
| FAQ | `content/data/faq.json` |
| Testimonials | `content/data/testimonials.json` |
| Old-URL redirects | `content/data/redirects.json` |

## Adding pages

```bash
npm run new <page|product|service|post|case> "Title"
```

Fill in the frontmatter it creates, then `npm run check`. A page is added by
creating the file — no other file needs to change.
